## Cross-cutting data boundary

- `src/api/client.ts` is the shared API boundary. The guard reads the Zustand in-memory mode as authoritative, rejects stored Demo as fail-closed too, and does not depend on localStorage being available. Unit tests verify JSON, FormData and SSE requests are stopped before `fetch` when storage reads throw. Production `src/state.ts` forces Live, so users cannot select Demo in a production build.
- CodeQ and Research GET event streams now use `apiStreamGet()` in `src/api/client.ts`; `WorkspaceScreens.tsx` keeps the same route, cursor and abort lifecycle. The shared helper applies the in-memory Demo guard before `fetch`, sets same-origin credentials and existing bearer/session headers, and parses the JSON event frames. Tests cover authenticated SSE headers/event parsing and no-fetch Demo rejection. This verifies the frontend guard with mocks, not real backend event delivery.
- Demo fixtures/providers live under `src/demo/`; Demo mode uses these local providers. `src/components/ExecutionTrace.tsx` owns synthetic local events, metrics, timers and sample outputs and is mounted only after explicit Demo operation signals.
- Live execution details must be driven by domain components, not `ExecutionTrace`. Live components currently confirmed in source: CodeQ event SSE and Research event SSE/checkpoint data. Models have polling. Other workspaces have run/job/status records or action responses but lack a verified incremental stream in the audited source.
- Auth/session headers and route ownership/permission checks remain in the current API/backend paths. This task did not weaken them. No authorization integration test was run against Python.
