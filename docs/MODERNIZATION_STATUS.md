# Modernization status

This page tracks the commercial-readiness work against the implementation brief. It describes this source tree, not an installed desktop copy or a certified hosted deployment. Optional providers and local model dependencies have to be checked on the machine where OpenAgent runs.

## Implemented and checked locally

- Startup rejects non-loopback binding unless team authentication is enforced or the explicit unsafe development override is set. Loopback single-user mode remains available.
- Password records use Argon2id; successful login upgrades legacy PBKDF2 records. The vault and security envelope readers can decrypt authenticated legacy records and rewrite them with AES-256-GCM.
- The local HTTP adapter applies request identifiers, body limits, security headers, CORS restrictions, and class-based rate limits. Read-only model inventory and auth status requests use the general limit; mutating model and login operations retain tighter limits.
- Module health now separates a responding status probe from feature capability. A responding probe is not evidence that an external provider, model, or workflow is operational. Most capabilities remain explicitly unevaluated by this endpoint.
- A shared egress client now covers several browser, research, scraper, calendar, webhook, OAuth, MCP, model-provider, model-download, ultra-model health/warmup, voice-model setup, and scientific-catalog paths. It requires approval for public destinations, pins resolved addresses, checks redirects, caps responses, and records local metrics. It is not yet the only network path in the product.
- A shared process policy is used by local voice conversion/transcription commands, safe terminal, CodeQ, scientific Python execution, configured scientific simulators, Integration Hub's fixed safe commands, and the Colab GPU probe. MCP stdio has a separate bounded JSON-RPC process path with executable resolution, filtered environment, timeout, output cap, and process-tree cleanup; its HTTP path uses the egress client. Other subprocess integrations still need to be moved to the shared policy.
- SQLite migrations have an ordered, checksummed registry for the core schema, vector-store tables, CalDAV sync tables, Integration Hub tables, contacts, Workspace items, assistant records, MCP configuration, Digital Twin, semantic memory, the encrypted vault, fine-tuning, scraper jobs, document-processing artifacts, media, voice, and AgentBridge tasks. Upgrade tests cover legacy rows, current-schema adoption, idempotency, and migration-history validation. Many other services still own their schema changes.
- Developer, Security/Privacy, Agents, Workspace, Assistant, Digital Twin, semantic memory, vault, Knowledge, fine-tuning, scraper, editor drafts, media/voice, and workflow routes now have concrete domain handlers, in addition to the earlier extracted route groups. Media/voice handlers own all 20 declared endpoint/method pairs; upload endpoints retain the existing bounded multipart callback. Workflow handlers cover the declared GET, POST, PUT, and DELETE contract, including layouts, runs, and triggers. `routes/runtime.py` still owns substantial dispatch and is not a thin adapter.
- Vault passphrase rotation now changes matching entries in one transaction. If an entry cannot be decrypted, the rotation fails without changing earlier entries.
- Static file serving checks path ancestry after resolution, so a similarly named sibling of the web directory cannot be served through a traversal path.
- The frontend has typed helper modules, a reproducible `esbuild` bundle, semantic view links, browser-history routing, and local SVG icons. The API client combines caller cancellation with its timeout and retries only read requests. The command palette reads its destinations from the sidebar and supports keyboard selection and focus return. Assistant, communication, model policy, privacy, calendar, personal context, scraper, and fine-tuning outputs show labeled data with a collapsed raw-data view. Hidden compatibility controls were removed: chat routing and speech fallback are visible in Settings, while voice history, Knowledge results, and Scientific AI use their active workspaces. The main controller is still a large `app.ts` with `@ts-nocheck`; this is a transition, not the finished domain-component architecture.
- Startup now requests data for the selected view instead of loading every module at once. The service worker caches only the versioned shell files and leaves unrelated GET responses alone. Navigation remains network-only so an offline old port cannot display a cached application shell.
- The Docker image and Kubernetes examples have authenticated team-mode defaults and non-root runtime controls. They are deployment baselines; no multi-replica Postgres deployment has been certified.

The local checks for this work use `python -m unittest discover -s tests -q`, `npm run check:web`, `npm run test:web`, `npm run build:web`, `npm run test:e2e`, and `python -m build`. Browser tests require an installed Playwright Chromium and a Python environment with OpenAgent's dependencies. `OPENAGENT_E2E_PYTHON` selects that interpreter when it is not the shell default.

On this Windows source checkout, the integrated Python suite passed 608 tests with one skipped. The run reported socket and HTTP fixture resource warnings but no failing assertions. The frontend typecheck, bundle build, and four unit tests passed. All nine Chromium journeys passed with `OPENAGENT_E2E_PYTHON` pointed at the project virtual environment. The browser executable could not launch inside the filesystem sandbox (`spawn EPERM`), so that run used an approved unsandboxed browser process. Wheel and sdist builds passed. Docker and Kubernetes smoke tests were not run because their CLIs are not installed here.

## Still required for the implementation brief

| Area | Remaining work |
| --- | --- |
| Data | Move the remaining service-owned DDL into ordered migrations. The current source scan finds 192 `CREATE TABLE` lines outside the migration registry and inactive legacy storage reference, across 29 modules. Resolve the shared `calendar_events` historical shapes, then add a shared-state Postgres adapter and tenant constraints before multi-replica server mode. |
| Backend | Extract the remaining domain dispatch from `routes/runtime.py` (4,344 lines after media/voice/workflow extraction); make every declared route resolve to a concrete handler; add an ASGI server after local-adapter parity. |
| Processes and network | Complete the inventory of direct subprocess and HTTP calls, migrate each behind the shared policies, and test cancellation and destination controls for each caller. |
| Frontend | Split the main controller into feature modules, remove `@ts-nocheck`, replace remaining raw diagnostic output with domain views, and validate more critical flows at desktop, tablet, and mobile sizes. The new generic result renderer is not a replacement for feature-specific views. |
| Capability truth | Make one runtime capability catalog distinguish ready, setup-needed, degraded, demonstration, unavailable, and certified states throughout the UI. |
| Operations | Add shared production metrics and traces, backup/restore drills, tenant quotas, provider certification, installer upgrade proof, and broader accessibility and security gates. |

Passing local tests is necessary but does not certify external providers, a production deployment, the installed desktop build, or scientific results. Those need their own environment-specific acceptance evidence.
