## Cross-cutting contract requirements

Every proposed contract must specify:

1. **Authentication and authorization:** use existing route scopes and owner/project checks; define read/write/admin scope per operation. Never trust client-supplied owner IDs.
2. **Isolation:** bind reads, writes, streams and stored artifacts to authenticated owner plus the approved workspace/project membership boundary. Use opaque identifiers with owner checks.
3. **Persistence:** identify source of truth, retention, deletion/restore semantics, migrations and idempotency before adding endpoints.
4. **Streaming:** define event schema/version, sequence/cursor, replay window, heartbeat, terminal state, cancellation, reconnect/backoff and queue bounds. A UI timer or percentage is not a backend event.
5. **Security:** bound payload size/rate/time, escape rendered text, validate path/resource identifiers, preserve network-consent gates, avoid credentials in events/logs, and avoid exposing cross-tenant data.
6. **Tests:** route contract and schema tests; owner/project isolation tests; unauthorized/forbidden tests; persistence/restart tests where durable; replay/reconnect/cancel/error tests for streams; resource cleanup and size/rate limit tests.
7. **Frontend state:** return enough typed fields to represent queued, connecting, running, streaming, waiting approval, retrying, completed, cancelled and failed where applicable; never infer success from HTTP acceptance alone.
